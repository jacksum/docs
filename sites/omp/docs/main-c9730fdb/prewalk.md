# 预遍历 \{#prewalk}

预遍历是在规划进入实现阶段后，从当前模型向更快或更便宜模型进行的一次性交接。它让起始模型先检查仓库、创建待办列表并开始修改，再由目标模型继续会话。

预遍历默认关闭。其目标为 `prewalk.into`，默认是分配给 `@smol` 角色的模型。如需让 OMP 逐任务决定一个提示是否值得使用预遍历，请参阅[自动预遍历](#auto-prewalk)。

## 启用预遍历 \{#enable-prewalk}

在全局配置中持久启用预遍历：

```bash
omp config set prewalk.enabled true
```

`~/.omp/agent/config.yml` 或项目 `.omp/config.yml` 中等效的 YAML 为：

```yaml
prewalk:
   enabled: true
```

`prewalk.into`（默认 `@smol`）设置交接目标，`prewalk.from`（默认 `@default`）设置规划模型：`/prewalk restart` 会返回该模型，自动预遍历的 `escalate` 模式也会在该模型上规划。两者都接受模型模式或角色。例如，在较慢的模型上规划，再交接给默认模型：

```yaml
prewalk:
   from: "@slow"
   into: "@default"
```

配置中的设置会为新会话准备交接，而不会为恢复/导入的会话准备交接。显式会话标志可以为两者准备交接：

| 标志 | 效果 |
| --- | --- |
| `--prewalk` | 为新会话准备预遍历交接。 |
| `--no-prewalk` | 即使 `prewalk.enabled` 为 `true`，也让启动会话保持禁用预遍历，并阻止[自动预遍历](#auto-prewalk)介入该会话。`/new` 仍遵循设置。 |
| `--prewalk-into <model-or-role>` | 准备预遍历交接，并使用提供的模型模式或角色代替 `prewalk.into`。 |

例如：

```bash
omp --prewalk
omp --prewalk-into @smol
omp --prewalk-into openai/gpt-5-mini
```

启动时，OMP 按通常的模型角色和模型匹配规则解析目标，依次尝试已配置的角色候选项，以找到具有已认证、已启用提供方的候选项。扩展提供的目标可能在扩展注册后解析。如果没有剩余的可用目标，OMP 会输出警告，并在未准备预遍历交接的状态下启动。

`--no-prewalk` 不能与 `--prewalk` 或 `--prewalk-into` 组合。显式的 `--prewalk-into @default` 会针对被 `--model` 覆盖之前的默认角色进行解析。

`/new` 使用 `prewalk.enabled` 和 `prewalk.into` 开始新周期，而不是继承已消耗的交接或上一次待办门控。启动标志（`--prewalk`、`--no-prewalk`、`--prewalk-into`）只适用于启动会话；`/new` 始终使用配置中的设置。启用预遍历时，交接后的新会话会恢复之前的规划模型和思考级别，除非之后的选择已将其替换。如果规划模型已无法使用（例如，其凭据已被移除），`/new` 会警告并保持使用当前模型。恢复现有会话不会自动重新准备预遍历交接。

交接后进行的任何模型或思考级别更改都算作替换，包括规划模式在进入和退出时执行的切换。自动重试回退、回退恢复和上下文升级不算；如果运行 `/new` 时，会话已回到交接模型和思考级别，它仍会恢复规划模型。

在交接仍在切换时做出的模型或思考级别选择优先，交接不会被记录，因此 `/new` 和下一任务都不会返回规划模型。如果你的选择发生在目标模型就位之前，切换会取消，并显示 `Prewalk: cancelled …` 通知，会话保持你的选择。如果目标模型已就位（例如，你选择了思考级别），会话会保持使用目标模型并采用你的选择，仍会收到实现检查清单。从自动交接返回时，同样不会覆盖在规划模型加载期间做出的选择。

## 交接触发条件 \{#handoff-trigger}

已准备的预遍历会注入规划提示。`todo` 工具处于活动状态时，任何成功的 `todo` 调用（包括只读的 `view` 操作）都会打开交接门控。没有活动的 `todo` 工具时，门控已经打开。

OMP 会在包含首个符合条件的 `edit` 或 `write` 结果的已完成助手轮次边界进行切换，且会先持久保存该轮次的助手消息和工具结果。与待办门控不同，编辑/写入触发不要求结果成功。

调用其他工具不会触发交接。不更改文件的 `write` 调用也不会触发：向 `agent://` 对等方发送消息、回复，以及对 `proc://` 的 stdin、mode 或 kill 写入。运行了工具命令的 `bash` 调用，只有在其分派记录将该运行归类为工作区写入时才计入；LSP 导航或 `<tool> --help` 查询这类只读分派不会准备交接，测试运行器或远程命令这类执行层分派也不会。

切换是一次性的：交接后，预遍历会解除自身的交接准备、移除规划提示，并通过实现检查清单引导目标模型。它会更改会话的当前模型和可选思考级别，但不会重写模型角色分配。同模型交接仍可以更改思考配置；模型与有效思考配置都已匹配时，预遍历会解除准备而不切换。

交接会记录在会话中，因此恢复会话、通过 `--restore` 还原会话，或唤醒已停放的子代理，都会继续使用交接模型和思考级别，而不是返回规划模型。交接后发生的重试回退会取代交接，与任何会话本地模型一样。唤醒的子代理在仍使用该目标时不会再次准备其预遍历交接。

## 从活动会话准备交接 \{#arm-from-an-active-session}

在顶层会话中，实时更改 `prewalk.enabled` 也会生效：开启时，如果尚未准备目标，就会准备向 `prewalk.into` 目标交接；关闭时，会解除待处理的交接准备。这不控制子代理预遍历。

无需重启 OMP，即可运行这些斜杠命令：

```text
/prewalk [into]
/prewalk restart [from] [into]
/prewalk off
```

`/prewalk` 准备从当前模型到 `into`（任意模型模式或角色；默认 `prewalk.into`）的一次性交接。

`/prewalk off` 取消待处理的交接并清除其规划引导，而不更改当前模型、已保存的配置或已经交付的继续执行历史。在交接切换期间运行它会取消该切换。已关闭或已经交接后运行也是安全的；它本身不会切回规划模型，不过下一任务仍会从[自动交接](#one-task-at-a-time)返回。取消只适用于当前会话：配置中的设置启用时，`/new` 会重新准备预遍历交接。它也会阻止[自动预遍历](#auto-prewalk)再次准备交接，直到执行 `/new`。

交接后，`/prewalk restart` 会立即将会话返回 `from` 并重新准备向 `into` 交接；省略的参数使用 `prewalk.from` 和 `prewalk.into`。参数只适用于该次命令，不会被记住。选择器在命令运行时解析，因此角色重新分配会生效，且两个角色的持久配置都不会改变。

如果已经准备了预遍历交接，`/prewalk` 会保留现有目标。`/prewalk restart` 也会保留匹配的准备状态；如果现有目标与请求的 `into` 不同，restart 会在更改当前模型之前被拒绝。如需在启动时选择不同的目标，请使用 `--prewalk-into`。

## 自动预遍历 \{#auto-prewalk}

`prewalk.enabled` 和 `/prewalk` 无条件准备一次性交接。自动预遍历会逐任务询问 OMP 的原生评判器是否值得进行预遍历，值得时就从当前模型准备同样的交接。这是预遍历适用性检查，不是难度评级或通用模型路由器：在 `on` 下，它从不选择不同的规划模型；在 `escalate` 下，它用于规划的其他模型只有 `prewalk.from` 指定的模型。

```yaml
prewalk:
   enabled: false
   auto: on
   autoTarget: "@smol"
```

`prewalk.autoTarget`（默认 `@smol`）接受模型模式或角色，按通常的角色和模型匹配规则解析，包括认证。

| `prewalk.auto` | 行为 |
| --- | --- |
| `off`（默认） | 不分类。较早的自动交接仍会在下一任务时返回。 |
| `suggest` | 对每个新任务分类，只报告决策。从不准备预遍历交接；较早的自动交接仍会在下一任务时返回。 |
| `on` | 对每个新任务分类。当评判器确信任务适合，且目标能解析为具有可用凭据的模型时，准备从当前模型到目标的交接；否则不做更改。 |
| `escalate` | 类似 `on`，但评判器确信适合的任务会先移到 `prewalk.from` 进行规划，再从该模型交接。当 `prewalk.from` 已是当前模型和思考级别时，这相当于 `on`，但此时 `@initial` 没有可交回的目标。 |

先运行一段时间的 `suggest`，观察它如何评判你的提示，然后设置 `auto: on`。如需在更强的模型上规划，可以将它设为当前（`@default`）模型，或者将它设为 `prewalk.from` 并使用 `escalate`。规划模型不一定要更强；`escalate` 会在 `prewalk.from` 指定的模型上规划。

### 在另一个模型上规划 \{#plan-on-another-model}

```yaml
prewalk:
   auto: escalate
   from: "anthropic/claude-opus-4-5"
   autoTarget: "@initial"
```

在 `escalate` 下，评判器在任务起始模型上运行。当它确信适合时，OMP 会在其余设置之前切换到 `prewalk.from`，因此记忆召回、钩子、附件和自动思考都在规划模型上运行，该切换会在会话中显示为模型更改。随后从规划模型交接到 `prewalk.autoTarget`。使用 `autoTarget: "@initial"` 时，会交回任务开始时的模型和思考级别；当规划模型是同一个模型但思考级别不同时，这些操作只更改思考级别，从而保留提供方会话。`@initial` 需要一个被 `escalate` 移动过的任务：在 `on` 下，它会警告一次并改为交接给 `@smol`；留在起始位置的任务（见下文）已经在那里，因此不会准备交接；子代理始终为它使用 `@smol`。

只有 `escalate` 能移动的任务才会在设置开始之前等待评判器，因此这时评判器的时间上限为 1 秒而不是 4 秒，并在其运行期间加载规划模型的元数据和凭据。在评判器运行期间做出的模型或思考级别选择会让任务保持在你指定的位置。当 `prewalk.from` 已是当前模型和思考级别，或无法解析时，不会等待，评判器保留通常的预算，与 `on` 相同。不可用的 `prewalk.from`（无法解析或没有凭据）会警告一次，并让任务留在当前模型；之后按 `on` 处理，但 `@initial` 没有可交回的目标。`suggest` 会补充 `escalate` 将移到的规划模型，例如 `Auto-prewalk: prewalk 0.84; escalate would plan on anthropic/claude-opus-4-5`。

`prewalk.enabled` 保持原意：无条件预遍历，独立于 `prewalk.auto`。

### 要求 \{#requirements}

自动预遍历需要 `judge` 模型角色首先解析到原生评判后端，这与 `find.enabled: auto` 的条件相同。它使用现有的 judge 角色提供方支持，包括 TypeSafe `jev`、OpenRouter、OpenAI Decisions 和 Workers AI Clef。它依赖校准后的概率，从不执行通过提示词驱动的设备端或聊天评判器，即使 judge 角色缓存早于登录或发现变更也是如此。没有原生评判器时，不会分类，也不会报告任何内容。

### 它决定什么 \{#what-it-decides}

评判器根据任务中昂贵推理应发生的位置分类，而不是根据任务有多难或多大：

| 路由 | 含义 | 典型任务 |
| --- | --- | --- |
| `prewalk` | 困难的思考在前；一旦确定方法，剩余实现和验证的范围就是有界的。 | 在局部修改前追踪陌生子系统；在实现明确设计前阅读多个相互作用的文件；将问题诊断到具体修复；难点在于找到转换方式及其所有影响范围的迁移。 |
| `primary` | 在实现、调试或验证期间仍需要强推理，因此首次编辑就交接为时过早。 | 尚未解决的竞态或不变量；微妙的生命周期变更；初步查看后原因仍不明确的错误；高风险或算法上困难的变更。 |
| `direct` | 没有值得从中交接的前置阶段。 | 解释和只读问题；简单、机械或完全指定的编辑；很小的局部修复。 |

单凭工作量或难度都不会让任务成为预遍历候选，错误交接的成本比错过交接更高：评判器被要求在 `prewalk` 和 `primary` 之间选择 `primary`，对小任务选择 `direct`。OMP 只有在 `prewalk` 获胜**且**概率至少为 0.70 时才准备交接。该阈值固定，获胜但低于阈值的 `prewalk` 视为“否”。

`suggest` 为每个被评判的任务报告一行：

```text
Auto-prewalk: prewalk 0.84
Auto-prewalk: primary (prewalk 0.18)
Auto-prewalk: direct (prewalk 0.06)
Auto-prewalk: prewalk 0.55 (below threshold)
```

在 `on` 下，有把握的决策会显示通常的 `Prewalk: armed for …` 通知；其他决策只写入日志。规划提示随任务的首个请求发送，现有交接机制负责切换，其待办门控和首个 `edit`/`write` 触发条件不变。与配置启用的预遍历一样，已准备交接的任务会跳过 `todo.eager` 提醒，因为规划提示负责待办创建。

### 一次一个任务 \{#one-task-at-a-time}

自动交接属于准备它的那个任务。下一任务开始时，OMP 会返回该任务起始时的模型和思考级别（如果发生过 `escalate` 到规划模型的切换，则是切换前的状态），再评判新任务，因此 `primary` 任务绝不会留在交接目标上。`/new` 也如此。不论届时 `prewalk.auto` 设置为什么，都会返回，包括执行 `/prewalk off` 之后。任务从未使用过的自动交接准备会在下一任务时丢弃，新任务会独立评判。在任务仍使用规划模型时按 Esc，会让会话留在那里，下一任务则返回被中断任务的起点。

交接后显式选择模型或思考级别会接管控制：会话保持在你指定的位置。这种选择也会在待处理自动交接准备切换之前将其取消；包括规划模式在进入和退出时的切换、模型预设，以及扩展或 ACP 选择。由 `/prewalk`、`--prewalk` 或 `prewalk.enabled` 产生的待处理交接准备仍保持准备状态，自动预遍历从不还原它们的交接。

### 分类范围 \{#what-is-classified}

只分类顶层会话中由用户编写的新任务：键入的提示、用户调用的 `/skill:` 提示，以及排队后续消息交付时的任务。引导从不分类，因为它是在修订已经运行的任务。`ok` 或 `thanks` 等确认消息、合成的继续执行轮次、归属于智能体的消息、子代理、规划模式，以及已经准备预遍历交接的任务都会跳过。子代理有自己的逐智能体控制；见[子代理预遍历](#subagent-prewalk)。

评判器与其余提示设置（记忆召回、钩子、自动思考）并行运行，决策在请求发送前应用，因此只有当它是最慢的设置步骤时才会增加延迟。

像 `do that` 或 `continue` 这样的后续消息无法单独评判，因此评判器还会看到上一条实质性用户请求和智能体的最后回复，两者都会像其他小模型输入一样截断。当前请求仍具有权威性：上下文只用于解析它所指的内容。

### 手动控制优先 \{#manual-controls-win}

否定、direct 或低于阈值的决策，以及分类器错误，都会让模型、思考级别和预遍历完全保持原样。

由 `/prewalk`、`prewalk.enabled` 或 `--prewalk` 产生的待处理预遍历绝不会被替换、重定向或重新分类。`/prewalk off` 和 `--no-prewalk` 会阻止自动预遍历介入会话（对 `--no-prewalk` 而言是启动会话），直到执行 `/new`，两者都不会切换模型。显式的 `/prewalk` 或 `/prewalk restart` 会接管待处理的自动交接准备，此后它的行为与手动准备相同。

### 失败行为 \{#failure-behavior}

自动预遍历是一项优化，失败时放行。缺少原生评判器、评判器出错或回答格式错误、超时（4 秒，或对 `escalate` 能移动的任务为 1 秒）、中止，或评判器运行期间提示被取代，都使任务完全保持没有自动预遍历时的状态。概率无效、获胜路由不一致或置信度无效的回答会被拒绝。评判器失败以及每次评判耗时会被记入日志而不显示；不可用的目标会报告 `Auto-prewalk not armed: target …` 警告。评判会以 `auto-prewalk` 用途记入模型用量日志。

## 子代理预遍历 \{#subagent-prewalk}

任务子代理有独立的预遍历控制：智能体 frontmatter、`task.prewalk` 和逐智能体的 `task.agentPrewalk` 覆盖。它们的优先级和目标选择见[任务智能体发现](./task-agent-discovery.md)。

这些控制会无条件准备交接。`task.agentPrewalkAuto` 则让评判器逐项分配决定：

```yaml
task:
   agentPrewalkAuto:
      task: "on"
      builder: "openai/gpt-5-mini"
```

每个条目将智能体名称映射到 `"on"`（交接到 `prewalk.autoTarget`）、`"off"`，或目标模型模式或角色。缺失条目的行为与 `"off"` 相同。

评判在生成时针对分配文本进行一次，使用与自动预遍历相同的原生评判器、路由和固定 0.70 阈值（见[它决定什么](#what-it-decides)和[要求](#requirements)）。准备交接时，子代理获得的交接与无条件子代理预遍历相同；否则不使用预遍历运行。

来自智能体 frontmatter、`task.prewalk` 或 `task.agentPrewalk` 的无条件交接准备优先，且从不评判。逐调用指定模型和受限工具（规划模式）的生成会跳过，不进行评判，目标不可用或等于起始模型和推理强度的生成也会跳过。

子代理自动预遍历失败时放行：缺少原生评判器、评判器错误、超时或信息量不足的分配，会让生成的子代理不使用预遍历。它独立于 `prewalk.auto`。保持存活的子代理会为后续消息保留生成时的决策。子代理会话开始后，评判会以 `auto-prewalk` 用途记录到该会话的模型用量中。
