# wait \{#wait}

> 没有其他工作可做时，阻塞等待下一个后台结果、对等消息或引导中断。

## 来源 \{#source}

- 入口：`packages/coding-agent/src/tools/wait.ts`
- 面向模型的提示词：`packages/coding-agent/src/prompts/tools/wait.md`
- 作业交付：`packages/coding-agent/src/async/job-manager.ts`

## 输入与可用性 \{#input-and-availability}

`wait` 没有参数。它是一个基础的、需要读取批准且可中断的工具，在启用异步作业、对等消息或受监督服务时可用；它不选择特定的对等方或作业。

## 行为 \{#behavior}

- 在第一个属于调用方的作业结束或对等消息到达时返回。本次调用交付的作业结果会被消费，因此之后不会再有重复的异步结果。
- 每个已结束作业的 `Delivery:` 行区分四种情况：已被之前的调用消费；由本次调用交付（调用开始时作业尚未结束）；由本次快照移交，替代了作业排队中的完成推送，因此之后不会再有重复结果；以及真正迟到的结果，保留“未自动交付”的措辞，并补充其在调用前多久完成。入口状态来自 `settledJobIds()`（判断是否属于集合，而非比较时间戳），`JobSnapshot.settledAtMs` 携带完成时间。
- 引导/工具中断返回 `Wait interrupted by message.`，并设置 `details.interrupted=true`；其他中止向外传播。再次调用 `wait` 前，先处理传入通知。
- 调用方无法选择超时；`wait.idleTimeout` 设置决定作业和服务等待的空闲窗口（以下介绍默认值 `ladder`）。`30m` 等时长会以该单一窗口替代阶梯，用于每次空闲的作业或服务等待，也包括交互式会话；已用时间行，以及从第二次连续空闲等待开始出现的 `<system-notice>`，按下述方式工作。`none` 使作业和服务等待没有窗口：只有在所属作业结束或服务完成、直接消息到达，或引导或中止结束调用时才返回。回复等待和父级等待在所有模式下都保留阶梯。在 `ladder` 下，没有新消息的等待在 5 秒后返回仍在运行的快照（`useless`），之后每次连续空闲等待都在最高窗口后返回（默认 4 分钟；若会话跟踪更长的提示词缓存生命周期，则为 `ttlMs - 1m`，最长 30 分钟）；任何返回新消息的等待，或离开 `wait` 达 60 秒，都会将其重置为 5 秒。在顶层交互式会话中，等待所属作业从最高窗口开始：在那里提前返回只能结束其轮次，比阻塞到结果出现多花一次请求。如果连续等待是该轮唯一的工具调用，就直接进入最高窗口：智能体对空闲返回仅回应另一次 `wait`，说明它没有其他工作可做，因此提前返回只会消耗请求。最高窗口保持在会话的提示词缓存生命周期内（5 分钟或未知缓存为 4 分钟，1 小时缓存最长为 30 分钟），因此空闲返回仍能读取热缓存，同时避免长作业期间反复每 4 分钟唤醒（实时作业进度仍每 500 毫秒流式传到 UI）。已用时间行指明已花费的窗口，以及没有其他工作后应做什么：对于每个结果和消息都会开启其下一轮的顶层交互式会话（TUI 会话记录），指示其结束轮次；对于任何其他智能体，指示其立即再次调用 `wait`，不调用其他工具。从第二次连续空闲等待开始，已到时的等待会追加一个 `<system-notice>`，包含已等待的时间，告诉智能体推进所有不依赖该结果的工作，且不要为了持续调用 `wait` 而启动 `sleep` 作业。工具描述和该通知说明了如何等待没有作业报告的条件（CI 运行、部署、指定时间）：使用一个异步 `bash` 监视器，在条件成立时退出，然后结束轮次（顶层交互式会话）或调用 `wait`，由监视器完成来交付其结果，而不是要求用户稍后再来查看。
- 没有所属作业或服务在运行时，如果调用方在当前运行期间向某个智能体发送过直接消息（不是广播），该智能体此后尚未回答且仍在运行，则 `wait` 会阻塞等待回复。该智能体可通过直接回发消息（包括被唤醒子代理转发的轮次输出）回答，或通过结束调用方拥有的、属于该智能体的作业（其派生作业，或由调用方消息唤醒的轮次的作业）来交付结果。任何传入的直接消息（`agent://<id>?progress` 除外）都会结束 `wait`。`agent://all` 广播从不算作问题的答复：若 `wait` 正在阻塞等待回复时收到被询问智能体的广播，该广播会中断这次 `wait`，使之后的 `wait` 继续阻塞等待直接回复；此前收到的广播或来自其他智能体的广播不会结束 `wait`，会在返回时送达调用方。当没有任何被询问智能体仍能回答时，也会无错误结束：它们各自已结束轮次而未回复，或正阻塞等待调用方（在提问后进入、只能由调用方结果结束的 `wait`；它通过内联 `task` 派生调用方，正等待调用方完成；对调用方的无时限 eval 句柄等待）。无法到来的回复会导致双方都停驻。
- 来自被询问智能体的 `agent://<id>?progress` 消息不是其答复，不会结束 `wait`：只要该智能体仍存活（即使空闲），`wait` 就继续阻塞等待它，此后只有直接消息才算答复，`agent://all` 广播或发送该进度的轮次的已结束作业都不算。
- 其他情况会立即返回“没有可等待的内容”，并指明任何已结束却未回复，或在调用方完成前无法回复的被询问智能体。
- 没有所属作业时，服务完成会返回通知，指示调用方前往 `proc://` 查看状态/输出；有作业时，调用则返回它们当前的快照/结果。
- 即使不调用 `wait`，结果和对等消息也会自动交付。请继续有用的工作，而不是轮询。
- 首先检查排队的对等消息。已经结束但尚未交付的所属作业无需再次等待即可返回。即使执行前已排队唤醒，`wait` 仍会排出其消息或所属作业，而不是被跳过；宿主所有的通知在正常等待结果之后的下一个边界注入。若对等消息在与作业完成的竞争中先到，该作业仍可正常异步交付。
- 存在更新回调时，作业等待每 500 毫秒发出进度快照。作业结果/快照使用 `details: { op: "wait", jobs: ... }`；对等消息结果使用消息结果结构。
- 运行中的子代理行携带其最新进度，例如 ``- `AcpSurface` [task] — <label> — 5h7m · 90 req · $18.40 · ctx 160K/1M · stage: <stage>``：运行时间、请求数、费用、上下文占用、自估完成度和阶段，具体取决于其进度记录报告了哪些信息。Bash 和 eval 行，以及没有进度记录的 task 行，保持为 ``- `<id>` [<type>] — <label>``。`read proc://` 和 `read proc://<id>` 在运行中的 task 行上显示相同的进度。

## 相关接口 \{#related-surfaces}

- `read proc://` 列出调用方可见的作业和项目服务；`read proc://<id>` 查看状态/输出，不消费交付。
- `write proc://<id>/kill` 取消作业或所属子代理，或停止服务；发送空 `content`。写入裸 `proc://<id>` 仅向服务发送标准输入，包括空输入。
- `write agent://<id>` 发送对等消息；`agent://all` 仅允许主智能体向可见的存活对等方广播。裸 `read history://` 发现已注册智能体的会话记录。子代理的最终结果会自动交付给其父级。
- 使用 `bash` 的 `name` 和可选 `ready` 启动受监督服务；通过 `proc://` 查看和控制它们。
