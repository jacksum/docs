# TUI 运行时内部机制 \{#tui-runtime-internals}

本文档说明交互模式下终端输入与渲染的职责归属。终端写入不变量参见 [`tui-core-renderer.md`](./tui-core-renderer.md)。

## 职责归属 \{#ownership}

- **`packages/tui`**（`@oh-my-pi/pi-tui`）负责终端生命周期（`host.ts`）、驱动（`driver/`：输入解码、探测、帧写入器 `driver/output/writer.ts`、图片）、终端后端（`term/backend.ts`：历史批次、提交前沿、自然流式输出、视口分配、重放、关闭时刷新）、绘制器（`term/painters/`）和原生 Tern 后端（`native/`）。
- **`packages/coding-agent`** 负责会话语义：构建表面（`src/modes/interactive/`：会话记录作为 `main`，输入编辑器/状态/HUD 作为 `dock`），并在消息和工具最终确定时确定对应块。工具外观负责渲染视口分配结果（`src/ui/styles/tools/block.ts`）。

终端后端绝不会解读消息、工具或会话记录块：它看到的是 `main` 节点、节点的确定标记，以及其绘制器返回的行（和稳定头部）。

## 启动与根合成 \{#boot-and-root-composition}

`startHost()` 启动驱动、协商 TSP，并原生渲染（Tern）或使用 `TermBackend` 渲染程序的 `Surface`。编码智能体的帧将会话记录块放在 `main`，将实时界面元素放在 `dock`。

`HostOptions.screen`（编码智能体的 `tui.screen`，也会为预绘制帧缓存）选择终端后端的屏幕模式：`inline`（见下文）或 `fullscreen`，后者的每一帧都是备用屏幕帧，停靠区固定在底部，`main` 在应用拥有的窗口中滚动（参见[全屏屏幕模式](./tui-core-renderer.md#22-fullscreen-screen-mode)）。它可以在运行时更改；Tern 忽略它。在全屏模式中，除非禁用 `tui.fullscreenMouse`，否则外壳会请求拖动和焦点报告（或者在使用 `tui.mouse` 时请求悬停报告），让选择和滚轮输入能够到达窗口。输入编辑器会优先于编辑器路由 `app.transcript.*` 操作（补全弹窗保留自己的翻页处理）；提交提示后会再次跟随尾部。

每个终端帧（`TermBackend.#compose`）：

1. 绘制停靠区；屏幕剩余高度就是 `main` 的空间。
2. 在行空间压力下，提供提交前沿之后为容纳活动尾部而需要退役的已确定前缀，或第一个活动块的稳定行（流式头部）。丢失历史的显示则会收到重放批次（账本，随后是同一帧中退役的内容）。
3. 在活动块之间分配空间（见下文），并合成各层。
4. 将一个 `FramePlan` 交给驱动；获得确认的批次会提交其块，并安排下一帧。

欢迎块是普通的已确定 `main` 块：屏幕有空间时留在视口中，内容溢出时首先退役。

## 输入与焦点 \{#input-and-focus}

输入路径（终端后端）：

`stdin -> driver tokenizer -> decoder -> host intercept -> onKey bubbling -> focused widget -> host onKey`

`packages/tui/src/driver/input/tokenizer.ts` 会跨多次读取重组碎片化的 CSI/SS3/OSC/DCS/APC 序列和括号粘贴（单独的 ESC 在超时后变为 Escape）。`decoder.ts` 将其转换为 `InputEvent`；`keys.ts` 为每个按键提供规范的 `KeyEvent.id`（`ctrl+c`、`shift+enter`、…）和 `kind`（`press`、`repeat`、`release`）；`replies.ts` 将终端报告（探测响应）路由给各自所有者，使其绝不进入输入监听器。

宿主的 `intercept` 最先看到每个解码事件，并可消费它（coding-agent 的 `Shell` 将其用于输入拦截器）。随后，`TermBackend`（`packages/tui/src/term/backend.ts`）沿焦点路径路由按键（`packages/tui/src/dispatch.ts`、`bubbleKey`）：从获得焦点的节点向上传递给 `onKey` 处理器，然后传给获得焦点类型的控件（`term/widgets.ts`、`term/widgets/*`：编辑器编辑、选择器选择/激活、按钮操作），最后传给宿主的全局 `onKey`。粘贴会交给 `onPaste` 处理器和控件的 `paste`；鼠标点击通过上一帧的命中区域解析。

控件从控件键位映射读取按键（`packages/tui/src/term/keymap.ts`：`select.*`、`editor.*`）；coding-agent 通过 `setWidgetKeymap`（`packages/coding-agent/src/config/keybindings/keybindings.ts`）根据用户快捷键填充它。匹配器忽略按键释放。

`Surface.focus(node)` 移动焦点；两个后端都会在获得焦点的节点上绘制插入光标/焦点框，`editor`/`input` 绘制器会定位终端光标。在 Tern 下，终端自行处理输入并发送结果事件，原生后端再将其路由到相同的节点处理器。

## 显式会话记录生命周期 \{#explicit-transcript-lifecycle}

`main` 按语义顺序保留块：

- **活动**：尚未确定，可变且驻留于视口（流式头部可以在确定之前将稳定行移入历史）；
- **已确定**：已经调用 `settle(node)`，已最终确定但仍驻留于实时视口；每帧按当前宽度重新绘制（因此调整大小会使其重新排版），直到行空间压力使其退役，而且只退役不再能容纳的行，因此已确定块可以部分位于历史中，其余部分仍重新绘制（例如工具卡片在其历史行下方通过 Ctrl+O 折叠）；
- **已提交**：其所有行均已获写入器确认。已提交块始终按提交顺序形成 `main` 的前缀（提交前沿）。

确定后面的块绝不会绕过前面尚处于活动状态的块：退役会取出前沿之后、为使活动尾部能够容纳而必须移走的已确定前缀行（先是整块，然后是空间边界所在块的前导行），在第一个活动状态块处停止，并持续提供该批次，直到 `present()` 确认。如果显示丢失，或决定该批次的任何内容发生变化，包括几何信息、`main` 中的块，或其绘制的任意块的行（活动尾部缩小后不再对其形成压力），就会以新 id 重新准备尚未写入的批次。`retired(node)` 包含待处理批次，因此移除或重绘它们会触发重放；`contentInHistory(node)` 只计算该节点自身写入且已获确认的行，不包括分隔符或与其他块一同提交的空块。仅追加头部（`Block.stable`，例如流式 Markdown）也可以在压力下发出单调扩展的稳定行前缀，数量绝不超过压力要求；最终退役时只发出剩余部分。后端每帧都会检查部分位于历史中的块是否仍以已写入的行开头；如果在同一宽度下改变了这些行，就会重放历史。宽度变化后，历史中的前缀（按写入时的宽度保留）改为根据字母和数字映射到新行（不重放：`preserve` 和就地调整大小会保留滚屏历史；这些策略下内容溢出时，压力会移动完整块和完整稳定头部，因此映射精确）。在历史上方插入块、移除部分位于历史中的块，或重排已提交块，都会重放历史，因此每个块都会按顺序写入一次。后端在停止后重新启动（例如外部编辑器）时也会重放历史。

显示重放会以新 id 按当前宽度重写已提交账本，随后写入同一帧中退役的内容（包括稳定头部行）。它绝不会回退提交前沿。

分隔符：`separator(above, below)` 空行位于非空块之前，随该块一起写入历史（或显示在视口中），绝不会跨批次重复。

## 视口分配与工具折叠 \{#viewport-allocation-and-tool-collapse}

活动尾部能够容纳时，会完整显示。尾部更高时，按最新优先分配：先预留停靠区，每个活动（尚未确定）块至少获得一行，较新块获得剩余空间，已确定块获得最后剩下的空间。当活动状态块数量超过行数时，最新的 `rows - 1` 个块各保留一行，上方显示一条有界汇总行（`⋯ N more running`），绝不会为此提交或取消工作。分配的簿记复杂度为 O(视口)：尚未确定块的索引是基于 `main` 和确定标记的记忆化结果。

分配行数少于自身行数的块，会按该高度绘制（`paint(node, width, height)`）；忽略高度的绘制器会被截取尾部。编码智能体的工具块（`src/ui/styles/tools/block.ts`、`paintAllocated`）负责紧凑呈现：

- 分配空间足够时使用自身外观；
- 两行：带标题的框架边缘；
- 一行：状态行（运行时显示旋转指示器）；
- 零行：不显示内容，但不改变执行或最终性。

绘制器标记为 `Block.covering` 的停靠区行（输入编辑器的补全弹窗）会绘制在会话记录上方：它们不会缩小 `main` 的空间，其下方的活动行只是隐藏，而不是退役。

视口一旦到达屏幕底部，在活动内容缩小时仍会保持高度：活动主区域行与停靠区之间的空行使停靠区保持在底部。填充不属于活动内容（退役和分配都不会计算它）；重放或调整大小会重置此状态（全屏层会使常规屏幕及固定状态保持原样）。

## 终端写入路径 \{#terminal-write-path}

后端向驱动交付一个 `FramePlan`（`packages/tui/src/driver/contract.ts`）：可选的历史批次（`{ id, rows, kind?: "append" | "replay" }`）、视口行、光标或全屏层。

写入器（`packages/tui/src/driver/output/writer.ts`）：

1. 在禁用自动换行的情况下，规范化每行并使其适配宽度。
2. 只追加尚未确认的历史 id，位置紧靠视口起始处（重放会先清除，除非 `append` 大小调整要求保留历史）。空视口下的历史以一个空行结束，光标停在该行上。
3. 就地重绘锚定的可变视口，只重写变化的行。
4. 清除视口下方的陈旧行。
5. 恢复自动换行、同步输出状态和光标状态。
6. 只有在输出目标接受写入后才确认历史 id。输出目标写入抛错会使写入器永久停止（之后不再写入或确认任何内容），并重新抛出异常。

仅含视口的帧无法创建历史。主题变化让原生历史继续由终端拥有；稳定后的大小调整可能按滚屏历史策略重放历史。

## 调整大小 \{#resize}

调整大小期间，写入器通常借用备用缓冲区。帧在其中显示视口尾部；提供的历史绝不会在其中得到确认（后端会按新宽度重新准备尚未写入的批次）。经过一段静默窗口后，写入器恢复常规缓冲区，并通过一次 DSR（CSI 6n）往返恢复视口锚点。停放光标的偏移量和陈旧视口行会按新宽度重新测量，在多路复用器内部也是如此。

直接终端使用保留底部的边界：`max(0, min(reported − reflowedParkOffset, height − staleReflowedRows))`。多路复用器的 CPR 响应则优先于该边界，因为高度缩小可能丢弃光标下方的行，而不是将光标上方的行推走。缺少响应时，会回退到保留的几何信息和跟踪的增长/缩小量；多路复用器超时或增长超时会在回退前重试一次。`FrameWriter`（`packages/tui/src/driver/output/writer.ts`）负责这些不同的锚点恢复路径。

Warp 是例外：它会在 `CSI ?1049h` / `CSI ?1049l` 时重新报告大小，因此借用该缓冲区会形成循环。Warp 在多路复用器/ConPTY 之外默认采用就地重绘；在多路复用器内，网格由多路复用器拥有，切换也由其自行消费，因此继承的 Warp 标记仍保留针对多路复用器调优的借用路径。`PI_TUI_RESIZE_IN_PLACE=1` 会强制就地重绘，即使在多路复用器或 ConPTY 内也是如此。`PI_TUI_RESIZE_IN_PLACE=0` 强制借用，即使在 Warp 上也是如此。切换写入后第一个仅高度变化 ±1 的 Warp SIGWINCH 会被作为该回显消费：借用操作拥有备用缓冲区时，会直接吞掉它，不进行探测（此时发出的 CPR 会获取备用网格的快照）；否则，会废弃进行中的锚点探测，并按回显尺寸重新发出，使早于该尺寸的 CPR 响应无法成为其锚点。之后真正的一行大小调整仍会重新启动事务。

ConPTY 宿主出于与多路复用器相同的原因，被排除在就地大小调整之外：conhost 拥有应用写入的网格，因此 `Terminal.hostOwnsGridOnResize` 会将这些会话路由到借用路径。在 conhost 上的测量表明，调整伪控制台大小会使其从 `CSI H` 开始以绝对寻址重新输出整个视口，即使应用没有写入任何内容；它还会将光标重新归位，因此大小调整后的 DSR 响应报告的是第 1 列，而不是停放的标记列，永远无法判定响应归属。在这里，就地大小调整的两个前提，即可恢复的锚点和没有其他主体重绘的网格，都不成立，因此会直接跳过锚点探测（无法归属的响应只会消耗该会话的一个标记列，并让稳定后的重绘等待完整超时时长）；稳定后的重绘以回退值为锚点，而 `ResizeScrollbackMode` 重建会擦除 conhost 的陈旧副本。两个例外会保留探测：在多路复用器内，由多路复用器而不是 conhost 根据其自身网格响应 DSR，因此响应可判定归属，且宽度重排与隐藏增长逻辑仍需要它；此外，`PI_TUI_RESIZE_IN_PLACE=1` 会在此强制就地调整大小，同时恢复 CPR 往返。

因此，Warp 拖动只会重新启动稳定等待窗口，在安静下来之前不进行绘制；每次拖动事件都会先将活动视口置空（备用路径的预擦除，但不借用），使缩小时的重排只能将已提交行或空行推入滚屏历史。唯一一次稳定后的重绘会运行相同的 CPR 锚点探测，并跳过 `ResizeScrollbackMode` 重放，因此原生滚屏历史保留其重排后的宽度，而不是通过 ED3 重新换行。全屏覆盖层拥有备用缓冲区期间到达的切换回显，会重绘模态界面，而不是对备用网格探测常规锚点。

借用缓冲区的大小调整稳定后，会应用 `ResizeScrollbackMode`。`rebuild` 使用 ED3 清除原生历史，并请求后端以新的单调递增 id 重放完整的已提交账本（以及随之退役的内容，包括流式头部的稳定行）。`append` 在宽度变化时，在保留的历史下方执行相同的独立重放，跳过仅高度变化导致的副本。`preserve` 跳过重放，只重绘锚定的视口；历史保留旧宽度（后端根据文字将部分位于历史中的块映射到新宽度，参见会话记录生命周期）。底层默认值为 `preserve`；编码智能体设为 `rebuild`。

缩小时，应用收到大小调整通知之前，终端自身可能已经将活动视口行推入滚屏历史。写入器会计算终端推走了哪些行（先丢弃光标下方的空行，然后才推走顶部行），使用锚点恢复的光标报告确认，并在下一历史批次以相同行开头时跳过它们，因此缩小后退役的会话记录块不会写入两次。屏幕本身始终会收敛到恰好一个副本。同样，历史追加导致屏幕溢出时，写入器会先擦除旧的活动视口区域，使滚动只能将已提交行和空行推入滚屏历史，绝不会推入未完成的帧。

## 显式显示重置 \{#explicit-display-reset}

`Host.replayHistory()`（`driver.resetDisplay()`）具有破坏性，由用户触发。它用于会话替换、树/恢复替换、显示重置操作（默认为 Alt+L）、移除或重绘在历史中有行的块，以及重建语义会话记录的设置。下一帧会以一个新的单调递增历史 id 重放已提交的账本；它不会回退提交前沿。后端只在历史不再与账本匹配时自行重放：在已提交块上方插入了块，或流式头部的历史行发生了变化。普通渲染、动画和工具结束处理都无法触发它。

只影响当前/后续输出的主题或可见性更改会重绘可变视口；已退役的历史保持不可变。

## 浮层和图像 \{#overlays-and-images}

全屏浮层使用备用缓冲区，绝不追加历史。普通浮层只在可变视口上合成（在全屏屏幕模式下则覆盖整个帧，此时页面和选择器切换帧而不切换缓冲区）。

内联图像数据和清除命令在行放置之前发出。活动图像可以在视口中保持图形形式；已结束的历史使用文本回退，除非协议能够追踪稳定的物理行。

## 原生表面 \{#native-surfaces}

受支持的 Tern Surface Protocol 握手会绕过行/历史渲染器。
`Composer.describeSurface()` 将流动的会话记录作为 `main`，将实时
界面框架作为 `dock` 提供；终端负责布局和滚动。没有
语义 `describe()` 实现的组件回退为 `rows` 节点。调整大小会更新
回退宽度，而不重放历史，终端确认则控制
原生帧的节奏。参见[原生渲染](./tui-core-renderer.md#native-rendering-tern-surface-protocol)。

## 关闭 \{#shutdown}

`Host.stop()` 会在交还终端之前刷新（全屏时也是如此，除非禁用了 `tui.exitTranscript`：刷新帧是内联的，因此会话记录会落在普通屏幕上会话开始位置的下方）：`TermBackend.flush()` 会合成最后一帧，在待处理重放仍欠缺的账本内容之后，将每个仍驻留的 `main` 块按当前状态写入历史（无论是否已确定，都冻结下来），并以停靠区作为视口。浮层和全屏层不在其中。当写入器尚不能内联写入时（调整大小借用或静默调整大小、锚点探测），或者驱动因输出积压而跳过了它，写入器会保留该帧，并在 `FrameWriter.stop()` 中从视口顶部写入；随后退出任何备用缓冲区，将 shell 光标放在可见内容的紧后方，并在驱动恢复终端模式之前恢复自动换行和光标。`Host.suspend()` 不会刷新；外部程序返回后，后端再次启动时会重放历史。
