# Pi 的工作原理 \{#how-pi-works}

Pi 协调模型请求、工具执行、上下文组装和会话存储。会话是 Pi 保存的对话记录，包含消息、工具调用及其结果、模型切换、上下文压缩和其他事件。

会话中的消息和事件构成一棵树。树中的每条路径都是一个分支。以当前条目为终点的分支是活跃分支，它为下一次模型请求提供历史记录。

## 智能体循环 \{#agent-loop}

提交的消息会加入活跃分支。Pi 根据系统提示词、活跃分支、可用工具和模型设置构造请求，再通过所选的模型提供方发出请求。

模型提供方以流式方式返回助手回复，其中可以包含文本和工具调用。Pi 记录回复，执行每个工具调用并记录结果。至此，一轮交互结束。如果工具结果或排队消息需要再次请求模型，Pi 会开始下一轮；否则，本次运行结束。

引导消息会在当前助手轮次结束后加入。后续消息会在智能体完成待处理工作后加入。中止会停止当前运行，并将排队消息送回编辑区。

## 上下文 \{#context}

活跃分支提供对话历史。Pi 将该分支中的会话条目转换为模型可接收的用户消息、助手消息和工具结果消息。

Pi 根据自身的基础指令和发现的上下文文件构造系统提示词。请求还包含工具定义和技能描述。

完整的技能指令按需加载。扩展可以添加指令或转换上下文。

提示词模板会先展开编辑区里的输入，再生成用户消息。选中的文件、图片、粘贴的文本以及 Shell 输出都可以成为消息内容。

## 会话 \{#sessions}

持久化的会话保存为 JSONL 文件。树中的每个条目都有 ID，并引用其父条目。当前条目确定活跃分支。

从较早的条目继续对话，会在同一个文件中创建另一个分支。派生或克隆会话时，Pi 会将选定的历史记录复制到新的会话文件中。

Pi 根据活跃分支重建发送给模型的上下文。压缩会插入一条摘要，后续模型请求会用它替代较早的消息。原条目仍保留在会话树中。

## 接口 \{#interfaces}

交互模式在终端中呈现会话和智能体事件。输出模式处理一条提示词并输出最终回复。JSON 模式以 JSONL 格式输出智能体事件。

RPC 模式从标准输入接收 JSONL 命令，并将响应和事件写到标准输出。TypeScript SDK 在进程内创建和控制智能体会话。

所有接口都采用相同的智能体和会话机制。

## 扩展和资源 \{#extensions-and-resources}

扩展是加载到 Pi 进程中的 TypeScript 模块。扩展的工厂函数注册工具、命令、快捷键、模型提供方、事件处理器、渲染器和终端界面。

技能提供按需加载的指令和配套文件。提示词模板提供可复用的消息文本。主题提供终端配色。Pi 包通过 npm 或 git 分发这些资源。

## 信任和权限 \{#trust-and-permissions}

Pi 在加载项目设置和资源之前，先确定是否信任项目。作出信任决定并完成项目资源加载后，Pi 再加载上下文文件。启用的工具使用 Pi 进程的操作系统权限。扩展在该进程内执行。
